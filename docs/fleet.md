# 多服务器与 Agent

主面板统一保存服务器、节点、用户、订阅和分流规则。本机与安装 Agent 的其他 Linux 机器分别运行自己的 sing-box 核心。

Agent 主动连接主面板的 `/agent/v1/ws`，通过 WSS 接收所属服务器的配置和限定管理指令，并上报资源、运行状态及累计流量。节点流量由客户端直接连接所属机器承载。主面板的域名、管理路径和节点的客户端连接地址分别配置。

## 接入条件

- 主面板保持单进程、单 worker 运行；公开访问地址填写 HTTPS 域名根地址，例如 `https://panel.example.com`，不附带管理路径。
- 反向代理允许 WebSocket 升级，保留 Agent 请求的 `Authorization` 请求头。`/agent/` 使用固定公共路径，不跟随自定义管理路径。
- 目标机器支持 systemd、amd64 或 arm64、Python 3.10 及以上。安装器支持 Debian／Ubuntu 的 apt 和使用 dnf／yum 的发行版；执行安装需要 root 或 sudo，安装命令本身需要已有 curl。
- 目标机器能访问主面板 HTTPS、系统软件源及 Python 软件包源；已具备 `flock`、`runuser` 等 util-linux 工具。
- 主面板提供目标 CPU 架构的统计版核心安装包。普通官方二进制不包含本面板所需的全部统计与连接身份扩展。

反代需要的 WebSocket 部分如下，合并到现有站点配置中；`map` 位于 Nginx `http` 上下文：

```nginx
map $http_upgrade $panel_connection_upgrade {
    default upgrade;
    '' close;
}

# 放在反代主面板的 location 内
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection $panel_connection_upgrade;
proxy_read_timeout 120s;
```

完整示例见 [Nginx 配置](../deploy/nginx-cloudflare.conf)。将示例域名替换为自己的域名。节点地址使用公网 IP 或直连域名，普通 Cloudflare HTTP 代理不承载这些原始节点端口。WSS 保护 Agent 到公开 HTTPS 入口的连接，源站链路仍取决于实际反代部署方式。

### 准备核心安装包

默认从仓库根目录的 `agent-cores` 读取文件，也可通过主面板环境变量 `PANEL_AGENT_CORES` 指定目录：

| 架构 | 文件名 |
| --- | --- |
| Linux amd64 | `sing-box-linux-amd64` |
| Linux arm64 | `sing-box-linux-arm64` |

在构建机的仓库目录执行，Go 版本要求与主面板核心相同：

```sh
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 ./deploy/build-core.sh "$PWD/agent-cores/sing-box-linux-amd64"
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 ./deploy/build-core.sh "$PWD/agent-cores/sing-box-linux-arm64"
```

构建脚本接受第一个参数作为输出文件，并自动创建父目录；它继承 `GOOS`、`GOARCH` 和 `CGO_ENABLED`。请像示例一样传入绝对路径，构建过程会切换到临时源码目录。

只提供实际需要的架构即可。将产物放到主面板可读取的对应目录；`/agent/manifest.json` 列出已准备的架构和 SHA256。安装器从已指定的 HTTPS 主面板下载 Agent 与核心，并检查清单、文件哈希和归档路径。公开安装包只包含代码与核心，不包含数据库、接入令牌或私有配置。

## 一条命令接入

1. 在主面板的“服务器”页面点击“添加服务器”，填写名称和客户端连接用的公网 IP／直连域名；按需设置机器月额度。
2. 保存后进入接入页，复制该机器专属的 Linux 安装命令，在目标机器执行。
3. 页面自动等待 Agent 回报；显示已连接后，点击“为这台服务器创建节点”。
4. 在用户编辑页勾选该机器的节点，保存并让客户端更新订阅。

安装命令中的接入码有效期为 **15 分钟**，仅可绑定一个 Agent 身份；过期后重新生成。生成新命令会替换未使用的旧接入码。接入应答丢失时，安装器保留待确认身份，允许同一身份重试，不会把接入码变成可共享的通用凭据。再次接入已安装机器时，必须使用它原来那条服务器记录生成的命令。

安装器创建独立的 `singpanel-agent` 系统用户及 `sing-panel-agent.service`，默认路径如下：

| 内容 | 路径 |
| --- | --- |
| Agent 程序、venv 与核心 | `/opt/sing-panel-agent` |
| Agent 身份、运行配置和持久化流量队列 | `/var/lib/sing-panel-agent` |
| systemd unit | `/etc/systemd/system/sing-panel-agent.service` |
| 本机统计与控制端口 | `127.0.0.1:19190`、`127.0.0.1:19191` |

Agent 无需对外开放管理端口；节点监听端口仍需按协议开放 TCP 或 UDP。已有代理服务不会自动迁移，创建新节点时要避开它们占用的端口。Agent 以普通系统用户运行，节点端口使用非特权端口。

服务检查：

```sh
sudo systemctl status sing-panel-agent --no-pager
sudo journalctl -u sing-panel-agent -n 100 --no-pager
```

不要把安装命令、Agent 身份文件或完整节点配置公开到日志、工单或仓库。

## 状态和维护

服务器页展示连接状态、最近心跳、核心和 Agent 版本、CPU、内存、数据目录所在磁盘、系统负载、运行时长、网速与网卡累计流量。展开“机器详情”可查看各网卡；未计入机器额度的虚拟网卡会单独标记。首次采样还未计算出速率时，界面显示待上报值。

连接在线与核心运行是不同状态：Agent 可以保持在线，同时按管理员操作或机器额度策略停止核心。连接已断开或远端心跳超过 35 秒未更新会显示未连接；已确认的配置版本、待同步配置和最近操作结果分别展示。主控每次收到报告后确认已落库流量，再返回当前配置与指令；正常无积压时 Agent 约每 5 秒交换一次。

“管理”菜单支持重新同步配置、重启／停止／启动核心、更新 Agent、生成接入命令、撤销接入和删除服务器。界面提示“指令已保存”代表已入队，实际完成以 Agent 上报状态为准。删除服务器前须移除其节点。主面板本机的核心操作位于“运行与维护”。

### 90 秒断联租约

主控为有效同步授予最多 90 秒的运行租约。短暂断联期间 Agent 保持最后成功配置并持续尝试重连；超过最后有效租约后自动停止它管理的代理核心。重连并收到有效配置后，按最新用户状态和机器额度恢复运行。手动停止或机器超额时不会仅因重连而重新启动。

因此主控长时间不可用也会影响远端代理可用性。维护、恢复备份和更改反代时需要预留这个窗口；租约控制不能代替精确的逐字节硬限额。

### 更新 Agent

在服务器的“管理”菜单点击“更新 Agent”。Agent 从当前绑定的主面板下载发布清单和代码包，校验 SHA256 与包内容后切换发布目录并重新启动。更新结果和上报版本显示在服务器卡片中；新版本未能恢复连接时有回退到上一份代码的恢复机制。

该操作更新 **Agent 代码**，不会自动升级 sing-box 二进制、系统包或 Python 依赖。先把期望的 Agent 版本部署到主面板，再触发远端更新。更新会短暂中断 Agent 及它管理的核心连接，离线机器需要恢复连接后执行待处理操作。

Agent 0.1.4 将 protobuf 固定到安全修复版 6.33.5。旧安装需使用原服务器记录生成的安装命令升级运行依赖；仅点击代码更新会明确拒绝依赖不一致的包，不会静默沿用旧依赖或另建机器身份。

Agent 0.1.5 支持官方 GeoSite 分类名中的 `!` 和 `@`，例如 `category-ai-!cn`；继续拒绝路径分隔符、点和控制字符。0.1.4 可直接通过“更新 Agent”升级，无需改变运行依赖。

## 节点与用户授权

新建节点先选择所属服务器，也可以从服务器卡片直接“创建节点”；协议切换会保留所选服务器。节点所属机器在保存后不能直接改动，需要在目标机器新建节点并重新授权用户。远端配置仅包含该服务器的入站；出口配置及凭据只下发该机器最终配置实际引用的出口，包括分流、默认出口、DNS、规则集下载及出口自身依赖所需的部分。所需 TLS 证书材料由主面板校验后随配置下发。

用户编辑页按机器分组节点，支持搜索机器／节点／协议、选择整组和选择当前显示项。“选择整台机器”勾选该机器**当前已有节点**，不自动授权以后新增的节点。

同一用户的所有已选节点，无论位于主面板本机还是远端机器，都共享一个流量额度、流量重置策略和有效期。用户停用、到期或额度用尽会在后续同步中更新各机器认证。远端报告使用服务器与核心 epoch 隔离的累计计数，重复提交不会重复计费；未确认报告在 Agent 本地保存后重传。用户用量在主控接收时入账：断联补报恰好跨过套餐重置、手工清零或每日／每小时边界时，总字节不重复，但补报增量会归入接收时的周期。当前不是按每个数据包发生时间恢复的分段账本。

### 在线用户与 IP 数限制

主控将本机连接与在线 Agent 的最新连接快照合并，按用户汇总在线状态、来源 IP 和连接数。每个 Agent 约每 2 秒检查自己机器上的用户 IP 上限，保留较早连接的 IP，断开新增超额 IP 的连接；主控再根据跨机器合并的快照执行全局限制，对远端下发对应用户与 IP 的断开指令。

每台 Agent 每次最多上报 **1000 条连接**，超过时设置截断标记。Agent 的本机检查仍遍历当前连接，但主控的在线统计与跨机器判断只依据已上报快照，大量连接时可能不完整。整个机制存在采样、上报和指令执行窗口，不是握手前或逐包的硬限制；同一 NAT 下多台设备共用一个来源 IP，因此 IP 数也不等于设备数。

## 机器月额度

机器额度与用户额度分开计算，主面板本机也支持设置。编辑服务器时可以设置：

- 每月额度，单位 GiB；`0` 表示不限量。
- 计费方向：接收 + 发送、仅接收，或仅发送。
- 每月重置日：1–28 日，**UTC+8 的 00:00**。

机器用量统计被标记为计额的物理／默认路由网卡，排除 loopback 和常见虚拟网卡。它包含这些网卡承载的整机流量及协议开销，不限于面板用户代理流量；按双向计费时，接收和发送都会计入。首次接入先建立计数基线，不把接入前的启动累计流量追记为当月用量。

达到机器额度后暂停该机受管理的代理核心；下个周期或提高额度后，若没有手动停止则恢复。它不会停掉系统其他网络服务。网络采样及控制同步存在延迟，可能短暂超额；跨月期间断联积累的差值计入后一次采样所在周期。此口径不能直接代替云厂商账单。

同一物理机的主控与隔离 Agent 如果上报相同 boot ID，顶部网速和流量汇总会去重，优先使用本机读数；实例在线数量仍分别显示。

服务器卡片的“网卡累计流量”是当前启动以来的网卡计数，“本月用量”是主控持久保存的周期增量；二者不应直接比较。用户套餐与每日用量仍按 UTC，机器月额度按 UTC+8。

## 当前范围

最多保存 100 台远程服务器。要求一个主控进程，不支持多主控自动切换、任意远程 Shell、跨机器节点自动迁移或面板内升级核心。Agent 拥有所属节点的连接认证材料；各服务器应由管理员控制和信任。

## 实时诊断

“服务器”卡片提供“监控与日志”入口，实时显示 CPU、内存、磁盘、网速与网卡累计流量。服务器列表及诊断详情使用 SSE，页面离开或进入后台时停止连接，回到前台自动重连。服务端每次推送重新检查管理员会话。

Agent 0.1.6 上报最近的核心日志，旧 Agent 可在管理菜单中更新；日志只对管理员开放，截断保存最新快照，敏感链接与常见凭据字段隐藏。界面支持暂停、搜索、级别筛选与复制。

“运行与维护 → 订阅拉取诊断”记录客户端实际拉取订阅的时间、用户、已识别客户端类型、格式、HTTP 状态、节点数和生成耗时。不记录订阅令牌、原始 UA、客户端 IP 或配置内容。自动保留 30 天且最多 10,000 条，筛选和游标分页保持固定窗口。上线前的请求无法追溯。

## 按机器发布与离线补报（Agent 0.2.0）

远端配置生成、规则准备及核心校验按服务器独立串行；不同机器可并行处理。相同输入复用已校验配置，连续变更在下一轮心跳合并为最新状态。共享额度与权限复验仍在短事务内统一完成。校验期间凭据、授权、节点或规则发生变化时，旧候选不会下发；失败的机器暂停授权租约，其他机器继续同步。失败状态按 30 秒退避，管理员可通过“重新发布”立即重试。界面区分等待合并、校验中、等待确认和已生效，只有远端运行回执能确认生效。

新 Agent 按 UTC 小时保存累计计数快照，已发送的批次冻结；新采样另开批次，断线后按顺序发送。每批包含原采样时间、核心 epoch 和递增序号。主控把用户额度、每日/小时历史、累计基线、批次序号及回执放在同一 SQLite 事务内提交；丢失 ACK 后重放不会重复计费。周期重置或手动清零后，旧周期补报只增加历史，不占用新周期额度。

这是按采样时间归档，不能从累计计数器还原两个采样之间每个数据包的精确时间。升级前旧 Agent 合并的快照无法恢复原小时，仍按旧协议兼容处理。网卡月额度独立于代理用户计费，仍按实际网卡采样间的差值计算。后台显示的是用户流量待确认批次数和最早采样时间。0.2.0 必须连接支持时间戳回执的新版主控，否则保留队列而不确认删除。

## ShadowTLS 组合节点（Agent 0.2.1）

0.2.1 支持 ShadowTLS v3 严格认证向无监听的 Shadowsocks 后端注入连接。
旧 Agent 不接受无端口后端，需先通过服务器管理更新 Agent 再创建远程组合节点。
只放行被严格 v3 包装器引用、没有 listen/listen_port 的 Shadowsocks 后端；
其他节点继续校验非特权端口与统计/控制端口冲突。流量计费只使用解密后端入站。
