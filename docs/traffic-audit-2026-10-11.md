# 流量计量实测（2026-10-11）

在实际部署服务器上，使用 `/opt/sing-panel/sing-box`（1.14.3，with_v2ray_api）与已部署的 panel.core / panel.runtime / panel.stats 代码运行。测试以 singpanel 身份创建独立临时数据库和环回监听，不修改生产用户、额度或节点，不重启生产核心。

## 字节对账

同一临时用户授权五个节点：Snell v5 独立/共享端口、Snell v6 独立/共享端口、VLESS Reality。每个节点均上传 1,048,576 字节、下载 2,097,152 字节 TCP 业务数据；再发送 4 个 512 字节 UDP 数据包，每包接收 1,024 字节回复。

| 节点 | TCP 上传 / 入库 | TCP 下载 / 入库 | UDP 上传 / 入库 | UDP 下载 / 入库 |
|---|---:|---:|---:|---:|
| Snell v5 独立端口 | 1,048,576 / 1,048,576 | 2,097,152 / 2,097,152 | 2,048 / 2,048 | 4,096 / 4,096 |
| Snell v5 共享端口 | 1,048,576 / 1,048,576 | 2,097,152 / 2,097,152 | 2,048 / 2,048 | 4,096 / 4,096 |
| Snell v6 独立端口 | 1,048,576 / 1,048,576 | 2,097,152 / 2,097,152 | 2,048 / 2,048 | 4,096 / 4,096 |
| Snell v6 共享端口 | 1,048,576 / 1,048,576 | 2,097,152 / 2,097,152 | 2,048 / 2,048 | 4,096 / 4,096 |
| Reality | 1,048,576 / 1,048,576 | 2,097,152 / 2,097,152 | 2,048 / 2,048 | 4,096 / 4,096 |

五个节点合并：上传 5,253,120 字节、下载 10,506,240 字节，差值均为 0。

额外检查通过：连续重复采样 5 次不重复累计；核心重启后已入库数据保留；第二位用户的用量保持 0；用户达到共享额度后，从全部五个入站撤销授权，其他用户保留。

## 大包 UDP 的独立发现

将每个 UDP 回复增大到 2,048 字节后：

- Snell v5 两种认证模式每包实际只收到 1,402 字节；四包共 5,608 字节，数据库也计入 5,608 字节。
- Snell v6 两种模式与 Reality 每包完整收到 2,048 字节；四包共 8,192 字节，数据库计入 8,192 字节。

这是当前测试路径的 Snell v5 大包 UDP 截断现象，尚未定位到上游实现中的具体原因；不属于把已转发字节计多或计少。测试没有改动核心来规避它。

## 计量范围与复现

统计代理承载的业务字节，不包含网络/IP/TLS 等开销，因此不能直接作为云服务商的网卡流量账单。此测试验证正常采样与核心重启，不能保证异常崩溃前尚未采样的数据不丢失；额度检查仍受约 2 秒轮询间隔影响。

```sh
PYTHONPATH=. SING_BOX=/path/to/sing-box python tests/traffic_audit.py
PYTHONPATH=. SING_BOX=/path/to/sing-box python tests/traffic_audit.py --udp-reply-bytes 2048
```

第二条命令对实际收发数据与入库数据作精确断言，并以 `udp_payload_intact: false` 单独报告截断。所有测试账户、文件与核心进程在结束时清理。
